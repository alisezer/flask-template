# flask-template

A Flask 3 starter that includes what a real project needs: an app factory, blueprints, SQLAlchemy 2 models, Alembic migrations, a validated JSON API, server-rendered pages, tests, CI and a Docker setup with nginx and PostgreSQL.

The example app is a small **short stories** site. You can create, read, edit and delete stories in the browser or through a REST API. It is kept small so the structure is easy to see. Replace it with your own domain.

The layout started from Miguel Grinberg's [flasky](https://github.com/miguelgrinberg/flasky), the companion project to his book *Flask Web Development*.

## Quick start

You need [uv](https://docs.astral.sh/uv/getting-started/installation/). It installs the right Python version for you.

```bash
git clone https://github.com/alisezer/flask-template.git
cd flask-template
cp .env.example .env
make install   # uv sync + pre-commit hooks
make migrate   # creates a local SQLite database (stories.db)
make seed      # optional: adds sample stories
make dev       # http://127.0.0.1:5000
```

Run `make` with no arguments to list every command.

## What's inside

| Concern | Choice |
| --- | --- |
| Web framework | Flask 3 with an application factory and blueprints |
| Database | SQLAlchemy 2 (typed `Mapped[...]` models) via Flask-SQLAlchemy; SQLite locally, PostgreSQL (psycopg 3) in Docker and production |
| Migrations | Alembic via Flask-Migrate; tested on SQLite and PostgreSQL |
| Configuration | `pydantic-settings`: typed, read from environment variables or `.env`, refuses to start in production without a real `SECRET_KEY` |
| API validation | pydantic v2 schemas, with 422 responses that name each invalid field |
| HTML | Jinja templates with Bootstrap 5 (follows the OS light/dark setting), Flask-WTF forms with CSRF protection |
| Serving | gunicorn behind nginx; `/healthz` checks the database |
| Quality | pytest (with coverage), ruff (lint and format), mypy (strict), pre-commit, GitHub Actions, Dependabot |

## Project layout

```
app/
  __init__.py      create_app(): wires config, extensions, blueprints, CLI commands
  config.py        Settings (environment variables -> Flask config)
  extensions.py    db, migrate, csrf; created unbound and attached in create_app
  models.py        Story model
  errors.py        HTML error pages, and JSON errors for /api/*
  logging.py       Logs go to stdout
  api/             JSON API blueprint (/api/v1): routes + pydantic schemas
  main/            HTML blueprint: views + WTForms
  templates/       Jinja templates
  static/          CSS, favicon
migrations/        Alembic environment and versions
tests/             pytest suite (API, views, config, migrations)
docker/            entrypoint and gunicorn config for the image
nginx/             Reverse-proxy config used by compose
```

To add a feature, add a model to `app/models.py` (switch to an `app/models/` package once there are several), add routes to a blueprint, then run `make migration m="describe the change"` and `make migrate`.

## Configuration

Settings come from environment variables, or from a `.env` file in development. See `.env.example`.

| Variable | Default | Notes |
| --- | --- | --- |
| `APP_ENV` | `development` | `development`, `testing` or `production` |
| `SECRET_KEY` | insecure dev key | **Required** in production. Generate one with `python -c "import secrets; print(secrets.token_hex(32))"` |
| `DATABASE_URL` | `sqlite:///stories.db` | `postgres://` and `postgresql://` URLs are given the psycopg driver automatically |
| `LOG_LEVEL` | `INFO` | |
| `SESSION_COOKIE_SECURE` | on in production | Set `false` only when serving over plain HTTP |

## JSON API

All endpoints are under `/api/v1`. Errors are JSON: `{"error": "...", "message": "..."}`. Validation errors return 422 with a `details` list.

| Method | Path | Description |
| --- | --- | --- |
| `GET` | `/stories/?page=1&per_page=20` | List stories, newest first, paginated (`per_page` is capped at 100) |
| `POST` | `/stories/` | Create a story. Returns 201 with a `Location` header |
| `GET` | `/stories/<id>` | Get one story |
| `PUT` | `/stories/<id>` | Replace a story (all fields required) |
| `PATCH` | `/stories/<id>` | Update only the fields you send |
| `DELETE` | `/stories/<id>` | Delete a story. Returns 204 |

```bash
curl -X POST localhost:5000/api/v1/stories/ \
  -H 'Content-Type: application/json' \
  -d '{"title": "Hello", "topic": "Intro", "author": "Ali", "text": "Once upon a time..."}'
```

The API is stateless JSON, so it is exempt from CSRF checks. Before exposing write endpoints publicly, add authentication (for example an API token checked in a `before_request` hook on the blueprint).

## Database and migrations

```bash
make migration m="add tags"   # autogenerate a migration from model changes
make migrate                  # apply pending migrations
uv run flask --app app db downgrade   # roll back one step
```

Review autogenerated migrations before committing them. `tests/test_migrations.py` fails if the migrations and the models drift apart. CI also runs the migrations against a real PostgreSQL.

To use PostgreSQL locally, set `DATABASE_URL=postgresql+psycopg://user:pass@localhost:5432/stories` in `.env`.

## Docker

`compose.yaml` runs a production-like stack: nginx → gunicorn → PostgreSQL 17.

```bash
echo "SECRET_KEY=$(python3 -c 'import secrets; print(secrets.token_hex(32))')" >> .env
make up        # http://localhost:8080
```

The image is a two-stage build (uv resolves dependencies, then a slim runtime image). It runs as a non-root user, has a healthcheck, and never contains your `.env`. Migrations run on container start. Set `RUN_MIGRATIONS=0` to turn that off, for example when you run several replicas and migrate in a separate release step.

## Tests and code quality

```bash
make test   # pytest + coverage
make lint   # ruff check, ruff format --check, mypy --strict
make fmt    # auto-fix formatting and lint issues
```

Tests use a temporary SQLite database per test, so they need no services.
